On Windows, sandboxed commands run in a Microsoft eXecution Container: they can read the system drive except `read.denyOnly` (other drives only where the working folder, a write grant or `sandbox.filesystem.allowRead` covers them), write only `write.allowOnly`, and reach the network only through the sandbox proxy. They cannot connect to localhost (127.0.0.1 or ::1) otherwise, and `sandbox.network.allowLocalBinding` does not apply on this backend: a command that needs a local port works only outside the sandbox, which is the user's decision, not yours. `$env:TEMP` is a folder of the command's own, deleted when it ends: put a temporary file that the user or the ${…}, ${…} and ${…} tools must open in the working directory, and delete it when done.
